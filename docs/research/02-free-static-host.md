# 02 — Which free static host can serve this

Status: research complete (ticket 02). Nothing deployed, no accounts created. Feeds ticket 09.
Labels: **verified** = a first-party doc/page states it (URL given). **inferred** = my reasoning from verified facts. **unverified** = not confirmed; listed under Open questions.
Sources were fetched during this session; the cloud docs carry 2026 'last updated' dates.

## Question

Which free host serves the Tetris lab (wasm, COOP/COEP cross-origin isolation, portfolio traffic, custom subdomain, deployable from Windows without Docker)?

## Hard requirements (from ticket)

R1 set `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp`
R2 serve `.wasm` as `application/wasm`, sane caching, brotli/gzip
R3 zero cost at portfolio traffic
R4 custom subdomain
R5 deployable from Windows, no Docker

## Options and per-host findings

### A. Cloudflare Workers Static Assets (recommended)

- Headers: `_headers` file, applied to static asset responses; per-path rules (`/*.wasm`, `/assets/*`); up to 100 rules, 2,000 chars/line; same-name headers from several matching rules are comma-joined. **verified** https://developers.cloudflare.com/workers/static-assets/headers/
- Headers do NOT apply to responses generated by Worker code. **verified** (same page). Implication: keep the app static-only.
- Default headers: `Content-Type` from file extension (Wrangler), `Cache-Control: public, max-age=0, must-revalidate`, `ETag`. **verified** (same page).
- Caching example for fingerprinted assets `max-age=31556952, immutable`. **verified** (same page).
- SPA fallback: `not_found_handling = "single-page-application"`. **verified** https://developers.cloudflare.com/workers/static-assets/routing/single-page-application/ and https://developers.cloudflare.com/workers/static-assets/
- Limits (Workers Free): 20,000 files per version; 25 MiB per file; 100 `_headers` rules; 2,000 chars/line. **verified** https://developers.cloudflare.com/workers/platform/limits/ (Static Assets table)
- Requests to static assets are free and unlimited. **verified** https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/ and https://developers.cloudflare.com/workers/platform/pricing/
- Workers Free daily cap: 100,000 requests/day, applies to Worker invocations (error 1027 when exceeded). **verified** https://developers.cloudflare.com/workers/platform/limits/
- Compression: `application/wasm` is in Cloudflare's compressible list (gzip, brotli, zstd). **verified** https://developers.cloudflare.com/speed/optimization/content/compression/ . Default between visitor and edge: Free = Zstandard; Pro/Business = Brotli. **verified** (same page, "Between visitors and Cloudflare"). Brotli on Free is therefore not the default. Compression Rules can override. **verified** that the override exists (same page); Free-plan availability **unverified**.
- Custom domain: Workers Custom Domains (`[[routes]] pattern = "...", custom_domain = true`); DNS + certificate automatic; requires an active Cloudflare zone; no wildcard DNS. **verified** https://developers.cloudflare.com/workers/configuration/routing/custom-domains/ . Headers survive on it: **inferred** (custom domain points the whole host at the same Worker/asset set; the `_headers` mechanism is per-response, not per-hostname).
- Preview: Version URLs from `wrangler versions upload` (`<prefix>-<name>.<subdomain>.workers.dev`). **verified** https://developers.cloudflare.com/workers/versions-and-deployments/version-urls/
- CLI on Windows: Wrangler is installed per-project via npm; **Windows 11 is a supported OS**. **verified** https://developers.cloudflare.com/workers/wrangler/install-and-update/
- Build minutes: no build step needed if you upload a built `dist/`; CI build caps are a Pages/Workers Builds concern, not checked here. **unverified** for Workers Builds quota.
- Bandwidth cap: none stated on the Pages or Workers limits pages I read (absence, **inferred**; Cloudflare's terms not checked).

### B. Cloudflare Pages (not recommended — Cloudflare's own steer)

- Cloudflare says "Are you sure you want to use Pages?" and that Workers is "Cloudflare's primary platform… Start new projects with Workers." **verified** https://developers.cloudflare.com/pages/
- `_headers`: same syntax, per-path, 100 rules, 2,000 chars/line. **verified** https://developers.cloudflare.com/pages/configuration/headers/ and https://developers.cloudflare.com/pages/platform/limits/
- Headers are not applied to Pages Functions responses. **verified** (headers page).
- Limits Free: 500 builds/month, 1 concurrent build, 20,000 files, 25 MiB per file, 100 custom domains per project, unlimited preview deployments. **verified** https://developers.cloudflare.com/pages/platform/limits/
- Works from Windows via Wrangler/Direct Upload. **inferred** from the Direct Upload and C3 mentions on https://developers.cloudflare.com/pages/

### C. Netlify

- Headers: `_headers` or `netlify.toml [[headers]]`, path wildcards/placeholders. **verified** https://docs.netlify.com/manage/routing/headers/
- Headers are global; cannot be scoped per branch/deploy context without a copy-the-file workaround. **verified** (same page).
- Custom headers do NOT apply to content from functions, edge functions, or proxies. **verified** (same page). Static only: fine.
- Default static caching: `Cache-Control: public, max-age=0, must-revalidate`; CDN `s-maxage=31536000`. **verified** https://docs.netlify.com/build/caching/caching-overview/
- Free plan is **credit-based**: 300 credits/month; bandwidth 20 credits/GB (≈15 GB/month); production deploy 15 credits (≈20 prod deploys/month); web requests 2 credits/10k. Unlimited deploy previews. **verified** https://www.netlify.com/pricing/ and https://docs.netlify.com/deploy/deploy-types/deploy-previews/
- Compression for wasm: **unverified** (I did not find the Netlify compression doc).
- Custom domain + headers: headers survive: **inferred** (served from the same site store).
- CLI from Windows: `npm install -g netlify-cli` (Node ≥18.14), `netlify deploy --prod`. **verified** https://docs.netlify.com/cli/get-started/ and https://docs.netlify.com/deploy/create-deploys/
- SPA fallback: redirect rule `/* /index.html 200` (standard Netlify redirect syntax) — **unverified** in this session (I read the headers and status-code pages, not the redirect page).

### D. Vercel Hobby

- Headers: `vercel.json` `"headers": [{ "source": "/(.*)", "headers": [...] }]`, per-source path scoping, applies to static files too. **verified** https://vercel.com/docs/project-configuration/vercel-json (#headers)
- Hobby is for **non-commercial, personal use only**. **verified** https://vercel.com/docs/plans/hobby . A portfolio site is arguably personal; a commercial product would not be.
- Hobby limits: 100 GB Fast Data Transfer/month; 10 GB Fast Origin Transfer; 1M CDN requests; 100 deployments/day; 100 builds/hour; CLI source upload cap 100 MB (Hobby). **verified** https://vercel.com/docs/plans/hobby , https://vercel.com/docs/limits
- Compression: brotli preferred over gzip; `wasm` is in the automatically compressed list. **verified** https://vercel.com/docs/how-vercel-cdn-works/compression
- SPA fallback: `rewrites` in vercel.json. **unverified** here (not read).
- Preview deploys: non-`--prod` CLI deploys create preview deployments. **verified** https://vercel.com/docs/cli/deploying-from-cli . Preview URL format: **unverified** (fetch of preview docs failed).
- CLI on Windows: `vercel` / `vercel deploy`. **verified** command forms; Windows install **unverified**.
- Custom domain + headers: **inferred** survive (headers are deployment config).

### F. Deno Deploy

- Headers: no config file; you write a server (`Deno.serve`) that returns static files with your headers. Full control over static responses. **verified** https://deno.com/blog/deploy-static-files (search excerpt; **verified** that it states "you have full control over all responses, even those to static files" — I read it as a search excerpt, not a full page fetch). Per-path scoping = your code.
- Free plan: 1M requests/month, 20 GiB egress, 5 custom domains, **no wildcard subdomains**, 10 active CPU-hr, 150 GiB-hr memory, 1 GB max deployment size. **verified** https://deno.com/deploy/pricing and https://docs.deno.com/deploy/pricing_and_limits/
- Deploy from CLI supported; GitHub deploys supported. **verified** https://docs.deno.com/deploy/
- Compression for wasm: **unverified**. Preview deploys: **unverified** (Deno docs mention cache-id and builds; not confirmed).
- Verdict: headers possible (R1 passes) but costs you a server file; Free plan's 5-domain limit is fine for one subdomain.

### G. Surge

- Headers: none configurable except CORS (`CORS` file or `config --cors`). **verified** https://surge.sh/docs/platform/ , https://surge.sh/docs/platform/cors
- So COOP/COEP cannot be set. R1 fails. **inferred** from the documented control-file list (`CNAME`, `.surgeignore`, `200.html`, `404.html`, `ROUTER`, `AUTH`, `CORS`).
- Gzip applied automatically; ETags; far-future caching. **verified** https://surge.sh/docs/platform/ . Brotli: not mentioned.
- Free: unlimited projects, custom domains, managed SSL, revisions. **verified** https://surge.sh/docs/platform/plans
- CLI: `npm install --global surge`, Node ≥18. **verified** https://surge.sh/docs/cli/

COOP/COEP are **not** on it. **verified** https://docs.codeberg.org/codeberg-pages/advanced-usage/

- Deploy: webhook or Forgejo Actions from a `pages` branch; no Windows CLI needed. **verified** https://docs.codeberg.org/codeberg-pages/

## Recommendation

**Cloudflare Workers Static Assets, static-only (no Worker script), served on a subdomain of a zone on Cloudflare.** Not Cloudflare Pages, because Cloudflare says new projects should start on Workers.

Main reason: it is the only host in the set that (a) lets you set COOP+COEP per path with a plain file, (b) costs nothing for static requests with no stated bandwidth cap, and (c) runs a Windows-native CLI from npm. Netlify and Vercel also pass R1 but have a tighter free bandwidth allowance (Netlify) or a personal-use-only licence (Vercel Hobby).

### Exact header config — `dist/_headers` (copy into the build output, e.g. `public/_headers`)

```
# COOP/COEP on every response (documents, workers, wasm): enables SharedArrayBuffer
/*
  Cross-Origin-Opener-Policy: same-origin
  Cross-Origin-Embedder-Policy: require-corp
  X-Content-Type-Options: nosniff

# wasm MIME, explicit (Wrangler already infers it from .wasm; this pins it)
/*.wasm
  Content-Type: application/wasm

# Fingerprinted build assets: cache forever (use a hashed filename convention, e.g. assets/[name]-[hash].wasm)
/assets/*
  Cache-Control: public, max-age=31536000, immutable
```

Rules for this file (all from the Workers headers doc): the `/*.wasm` rule must not set `Cache-Control`, or it would be comma-joined with the `/assets/*` value on any `/assets/…wasm` path (same-name headers are joined). Only `/assets/*` sets it. HTML keeps the default `max-age=0, must-revalidate`.

### Config — `wrangler.jsonc` (repo root)

```jsonc
{
  "$schema": "./node_modules/wrangler/config-schema.json",
  "name": "browser-tetris-lab",
  // set to the date you first deploy (YYYY-MM-DD)
  "compatibility_date": "YYYY-MM-DD",
  "assets": {
    "directory": "./dist",
    "not_found_handling": "single-page-application"
  },
  // custom subdomain (needs a zone on Cloudflare); uncomment after ticket 09 DNS check
  // "routes": [{ "pattern": "lab.example.com", "custom_domain": true }]
}
```

No `main` script: a static-only config. **inferred** that Wrangler accepts an assets-only config (the static-assets doc says "If no Worker script is present, a 404 is returned", which implies it is allowed). Verify at ticket 09.

### Deploy command (PowerShell on Windows, from the repo root, after `npm run build` writes `dist/`)

```powershell
npm i -D wrangler@latest
npx wrangler deploy
```

Preview before production: `npx wrangler versions upload` returns a Version URL (verified, Version URLs doc). Login is `npx wrangler login` (browser OAuth; not run here).

### Free-tier limit most likely to bite

**Workers Free: 100,000 requests/day** (error 1027 when exceeded). Static asset requests are exempt (verified), so for a static-only build it should not bite at portfolio traffic. It becomes binding the moment any path reaches Worker code (e.g. `run_worker_first`, a `/api/*` route, or a Worker used to add headers). Two things make that worse: requests matching `run_worker_first` get 429 instead of falling back to assets when over quota (verified, billing page), and Worker responses ignore `_headers` (verified). **Rule: keep the lab static-only and the cap stays inert.**

Runner-up for the "bites first" question if the host were Netlify: the 300-credit plan gives ≈15 GB/month bandwidth (20 credits/GB), verified on the pricing page. A ~2 MB wasm load per visit is ≈7,500 cold visits/month. That is the tightest number in this comparison.

## What would change the recommendation

- Cloudflare Free serving brotli-only clients uncompressed for wasm (Free default is zstd, verified): if ticket 09 shows wasm sent uncompressed to Chromium/Firefox builds, switch to Vercel Hobby (brotli default verified) if the site stays non-commercial, or add a Compression Rule if it works on Free.
- The lab becoming commercial or sharing a product: Vercel Hobby is out (verified licence); Cloudflare and Netlify remain.
- A need for server code (API, saved runs): Cloudflare Workers loses the static-only property, and the 100k/day cap becomes live; Deno Deploy (Free 1M req/mo) becomes the candidate instead.
- Cloudflare DNS not available for the portfolio domain: custom domain fails (verified: needs an active zone). Then Netlify (CNAME to its domain) is the fallback.
